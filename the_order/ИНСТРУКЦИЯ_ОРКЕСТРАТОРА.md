## 3. Как физически работать

- Облачная сессия **не запускает UE**. Сборка, редактор, тесты и скриншоты — только на ПК через мост:
  - `shell` — это PowerShell. Его рабочая папка **не** папка проекта, поэтому **всегда используй абсолютные пути** к проекту «Приказ».
  - Команда дольше 55 с возвращает `job_id` → `job_status(job_id, wait_seconds=55)` до `running:false`.
    Сборка UE идёт минуты–десятки минут, поэтому опрашивай job, не перезапускай команду.
  - Переменные не живут между вызовами `shell`, задавай их в начале каждой команды.
  - `screenshot` — снимок экрана для демо (у автора два монитора). Свои превью смотри сам, прежде чем показывать автору.
- Сборка без редактора: `<UE>\Engine\Build\BatchFiles\Build.bat CommandGameEditor Win64 Development -Project="<путь>\CommandGame.uproject" -WaitMutex`.
- Автотесты и прогоны: `UnrealEditor-Cmd.exe "<.uproject>" -ExecCmds="Automation RunTests CommandGame; Quit" -unattended -nullrhi -log`.
  FPS-метрики снимай в окне игры, а не в `-nullrhi`: `stat unit` / `stat fps` / CSV-профайлер. Цифры клади в отчёт.
- Где можно, пиши тесты кодом (Automation Spec / Functional Tests): парсер приказов, валидатор, ObjectiveTracker,
  PromptBuilder и пулы проверяются без человека. Визуальные критерии (обрушение, ragdoll, UI) — скриншот + лог.
- **Пишет в репозиторий на ПК только один исполнитель за раз**, иначе будут конфликты в `.uasset`, которые не мёржатся.
  Параллелить можно чистый C++ в разных модулях. Ассеты и карты — строго последовательно.

### Ловушки Спринта 6 (проверить до кода)
- Модель `Chun121/Qwen3-4B-RPG-Roleplay-V2`: убедись на HuggingFace, что **есть GGUF Q4_K_M**. Если есть только safetensors —

- Русский язык у RP-модели на 4B — главный риск качества. Прогони 20+ пар «приказ × набор ключей» и посчитай долю
  попаданий в характер. Если меньше 80 % — по ДИЗДОКу §I.17 резерв Qwen3-8B (предложи автору, не меняй сам).
- Генерация не блокирует game thread: отдельный поток / async-задача, токены идут в UI через делегат.
  Сначала прогрей модель (загрузка при старте миссии, а не на первом приказе).
- Параметры из ТЗ: `max_tokens=40`, `temperature=0.7`, `top_p=0.9`, `repeat_penalty=1.1`, контекст 2048.

- `StubLLMProvider` остаётся рабочим fallback: если модель не загрузилась, игра продолжает работать на заготовках.

## 7. Правила, которые не обсуждаются

1. **LLM = голос, не мозг.** Действия юнитов — только Behavior Tree. LLM выдаёт только текст. Любое предложение
   «пусть LLM решает, куда идти» отклоняется.
2. **Стоп-лист** (ТЗ, «Что НЕ делать»): не покупать ассеты, не моделить вручную, серый UI, без голоса и TTS,
   без физического стола и голограммы, без полной психологии, 10×10 вместо 100×100, без экономики, портреты — квадраты.
   Каждое «а давайте добавим» проверяй по ДИЗДОКу §IV.3: не служит критерию успеха MVP — откладывается.
3. Данные (ключи, офицеры, приказы, миссии) — JSON/DataTable в `/Content/Data`, не хардкод. Схемы — §III.5 ДИЗДОКа.
4. C++ с Blueprint-обёртками, каждая подсистема — свой модуль/папка по структуре ТЗ.
5. На ПК автора: не удалять и не перезаписывать чужое, не трогать другие проекты и их git.
   Ничего не устанавливать без согласия: движок, плагины, MCP-серверы, модели, чужие скиллы.
6. Ключи и токены не печатать и не запрашивать в чате.
7. Отчёт — только по фактам: если тест не прошёл, так и пиши, с цифрами и логом.
