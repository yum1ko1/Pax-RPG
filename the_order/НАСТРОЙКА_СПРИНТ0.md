# Спринт 0 — настройка окружения «Приказа» (runbook оркестратора)

Цель: на ПК автора собирается и открывается C++-проект `CommandGame` на **UE 5.8**, работает Unreal MCP, на месте плагин Llama-Unreal и модель,
есть git. Шаги с пометкой **[О]** оркестратор делает сам, шаги **[А]** — только автор (вход в аккаунты, окно UAC, освобождение диска).

Всё, что нужно автору, оркестратор отправляет **одним сообщением** по шаблону из конца файла и ждёт ответа «готово» по каждому пункту.

Факты, проверенные 27.10.2026:
- UE 5.8 требует Visual Studio 2022 **17.14+** (рекомендуется VS 2026), MSVC ≥ 14.38, Windows SDK ≥ 10.0.22621. На ПК стоит VS 2022 Community 17.14.6.
  Версия подходит, но нет нагрузок C++.
- Unreal MCP (плагин `ModelContextProtocol`) — экспериментальный, встроен в UE 5.8, слушает только `127.0.0.1:8000/mcp`.
- Llama-Unreal v1.4.0 (25.09.2026) собран под UE 5.8: `Llama-Unreal-UE5.8-v1.4.0-Vulkan.7z`, 25 МБ.
- Модель: `Chun121/Qwen3-4B-RPG-Roleplay-V2`, файл `unsloth.Q4_K_M.gguf`, 2.5 ГБ, лицензия MIT.
- На ПК есть: Claude Code CLI, git + git-lfs 3.7, tar (bsdtar), curl, winget, Python 3.14, Blender 5.2, Codex (вход выполнен). 7-Zip нет.
  ОЗУ 32 ГБ, RTX 5070 Ti.
- Свободно: C: ≈ 26 ГБ, D: 0, E: ≈ 33 ГБ. **Для движка и проекта этого мало.**

Набор файлов проекта: `C:\Users\mbkli\Desktop\The Order (Claude)\ue_kit\`. Внутри `.uproject`, `Source/`, `Config/`, `Scripts/`,
`CLAUDE.md`, `.mcp.json`, `.gitignore`, `.gitattributes`, `.claude/skills/`.
Ниже `$KIT` — эта папка, `$PRJ` — папка проекта, которую выберет автор (путь **без пробелов и кириллицы**, например `E:\CommandGame`).

## Шаги

### О1. Проверка окружения
```powershell
powershell -ExecutionPolicy Bypass -File "$KIT\Scripts\setup_check.ps1"
```
Выдаёт таблицу OK / НЕТ с подсказкой, что делать. По результату составь сообщение автору (шаблон внизу), в нём только пункты со статусом НЕТ.

### А1. Место на диске
Нужно: **≥ 15 ГБ на C:** (нагрузки VS) и **≥ 100 ГБ на диске для движка и проекта** (движок без отладочных символов, проект, DDC, модель).
Движок и проект лучше держать на одном быстром диске (SSD).
- [О] Помоги найти, что удалить, — только смотри, ничего не удаляй:
  ```powershell
  'Downloads','Desktop','Videos','Documents' | % { $p="$env:USERPROFILE\$_"; '{0,-10} {1,7:N1} ГБ' -f $_, ((Get-ChildItem $p -Recurse -File -ErrorAction SilentlyContinue | Measure-Object Length -Sum).Sum/1GB) }
  ```
- [А] Освобождает место: Параметры → Система → Память → «Рекомендации по очистке», удаление ненужного, перенос на внешний диск.
  Сообщает, какой диск отдаёт под движок и проект.

### О2 + А2. Нагрузки Visual Studio
- [О] Закрыть Visual Studio, если открыта, и запустить:
  `powershell -ExecutionPolicy Bypass -File "$KIT\Scripts\install_vs_workloads.ps1"`.
- [А] На экране появится окно UAC «Разрешить этому приложению вносить изменения?» → **«Да»**. Установка идёт 10–30 минут.
- Запасной путь, если скрипт не сработал: автор открывает «Visual Studio Installer» → у VS 2022 «Изменить» →
  отмечает «Разработка игр на C++» и «Разработка классических приложений на C++» → «Изменить».
- Готово, когда `setup_check.ps1` показывает OK у NativeGame, NativeDesktop, MSVC и Windows SDK.

### А3. Установка Unreal Engine 5.8 (только автор: нужен вход в аккаунт Epic)
1. Открыть **Epic Games Launcher** и войти в аккаунт.
2. Слева **Unreal Engine** → вкладка **Library** → рядом с «ENGINE VERSIONS» нажать **«+»**.
3. На появившейся плитке выбрать версию **5.8.x** (последний хотфикс) → **Install**.
4. Папка установки — на выбранном в А1 диске, например `E:\Epic\UE_5.8`.
5. **Options** (до начала установки или потом: стрелка на плитке → Options):
   - оставить: **Core Components**, **Engine Source** (исходники движка нужны Claude для сверки API);
   - **снять**: Starter Content, Templates and Feature Packs, **Editor symbols for debugging** (десятки ГБ; включить позже, если будет место),
     все Target Platforms (Android, iOS, Linux и т. д.).
6. Дождаться окончания (1–2 часа) и написать оркестратору «UE установлен».
- [О] Проверка: `setup_check.ps1` → «Unreal Engine 5.8 OK» и путь.

### О4. Создание проекта
```powershell
robocopy "$KIT" "$PRJ" /E /XC /XN /XO     # копирует набор, не перезаписывая существующие файлы
```
Если `$PRJ` уже существует и в нём что-то есть — сначала посмотри, что там, и спроси автора.

### О5. Git
```powershell
cd $PRJ; git init -b main; git lfs install; git add -A; git commit -m "CommandGame: каркас проекта (UE 5.8)"
```
Удалённый репозиторий подключается после А4.

### О6. Плагины в .uproject
`powershell -ExecutionPolicy Bypass -File Scripts\ue_plugins.ps1` → каждая строка должна быть «OK».
Строку «НЕТ» исправь по списку кандидатов — точное имя `AllToolsets` в шаблоне не подтверждено. Если не уверен — убери строку.
Там же найди плагин Fracture / Geometry Collection и добавь его в `.uproject`, если он не включён в движке по умолчанию.

### О7. Первая сборка и тест
```powershell
powershell -ExecutionPolicy Bypass -File Scripts\ue_build.ps1     # первый раз 5–15 мин
powershell -ExecutionPolicy Bypass -File Scripts\ue_test.ps1 -Filter CommandGame.Smoke
```
Падает — читай первую ошибку (скилл `ue-build-test`), чини каркас и коммить.
Частый случай: флаги в `Tests/SmokeTest.cpp` — сверить с `AutomationTest.h`.

### О8. Редактор и Unreal MCP
```powershell
powershell -ExecutionPolicy Bypass -File Scripts\ue_editor.ps1    # первый запуск компилирует шейдеры 20–60 мин
```
- Скрипт ждёт ответа `127.0.0.1:8000`. `.mcp.json` уже лежит в корне проекта.
- В **локальной** сессии Claude Code из `$PRJ`: `/mcp` → `unreal-mcp` подключён. Пробный вызов: «какие акторы на уровне?».
  При первом запуске Claude Code спросит, доверять ли MCP-серверу проекта, — подтвердить.
- Если сервер не поднялся: `Scripts\ue_log.ps1 -Pattern ModelContextProtocol`. В консоли редактора есть команды
  `ModelContextProtocol.StartServer` и `ModelContextProtocol.GenerateClientConfig ClaudeCode`.
- Из облачной сессии MCP недоступен (только loopback). Там работают сборка, тесты и логи через мост.
- Сразу после открытия редактора сохранить пустую карту `Content/Maps/L_Test_Combat` (через MCP/Python или попросить автора)
  и прописать её картой по умолчанию.

### О9. Плагин LLM и модель (спросить автора: «качаю плагин 25 МБ и модель 2.5 ГБ — ок?»)
```powershell
powershell -ExecutionPolicy Bypass -File Scripts\get_deps.ps1 -Plugin -Model
powershell -ExecutionPolicy Bypass -File Scripts\ue_plugins.ps1 -Find Llama
```
- Добавить плагин в `.uproject` (имя — из найденного `.uplugin`).
- Пересобрать с закрытым редактором.
- В логе редактора не должно быть ошибок загрузки плагина.
- Сама модель подключается в Спринте 6 (скилл `llama-unreal`).

### О10. Навигация по коду (необязательно, но полезно)
- `Scripts\ue_clangdb.ps1` создаёт `compile_commands.json` для clangd.
- Если в `/plugin` Claude Code есть LSP-плагин для C/C++ (clangd), установи его с согласия автора.
- clangd не входит в стандартную поставку. Варианты: компонент VS «C++ Clang tools for Windows» или `winget install LLVM.LLVM` (спросить автора).

### А4. Репозиторий на GitHub (только автор)
1. github.com → **New repository** → имя, например `the-order` → **Private** → без README → Create.
2. Дать доступ Claude: установить или настроить GitHub-приложение Claude для этого репозитория (claude.ai → Settings → Connectors / GitHub).
3. Написать оркестратору адрес репозитория.
- [О] Затем: `git remote add origin <URL>`, `git push -u origin main` (LFS-файлы уйдут автоматически).
  Учти: место под LFS на бесплатном GitHub ограничено. Крупные бинарники (модель) в репозиторий не кладутся — они в `.gitignore`.

### А5. Локальная сессия Claude Code (рекомендуется для всей работы с UE)
1. Открыть **PowerShell** или **Windows Terminal**.
2. `cd <путь к проекту>`, например `cd E:\CommandGame`.
3. Запустить `claude` и при вопросах о доверии к папке и MCP-серверу ответить «да».
4. Первое сообщение: «Ты оркестратор проекта Приказ. Прочитай CLAUDE.md и `C:\Users\mbkli\Desktop\The Order (Claude)\ИНСТРУКЦИЯ ОРКЕСТРАТОРА.md` и продолжай с текущего шага».
