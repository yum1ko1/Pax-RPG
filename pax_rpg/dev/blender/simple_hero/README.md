# Простой герой (демон с катаной) — Blender → glb

Временный герой из примитивов, пока нет готовой модели: жёсткие части (каждая — 100 % на одну кость), поэтому
кисти и локти не мнутся. Скелет — имена гуманоида Godot (Hips, Spine, Chest, LeftUpperArm…), плюс Weapon /
WeaponBack / WeaponHand для меча. ~7 тыс. треугольников, glb ~330 КБ.

Запуск в открытом Blender через мост (файлы — в `pax_corporations_dev\` игры):

1. `build_simple_hero.py` — сцена SimpleHero: тело, катана, ножны, риг, анимации Idle (60 к.), Walk (24),
   WalkArmed (24), Draw (36), Sheathe (36). 30 к/с.
2. `check_simple_hero.py` — рендеры кадров в `<W>/shots/sh_*.png` (смотреть перед экспортом!).
3. `export_simple_hero.py` — `<W>/hero_simple.glb` + проверка обратным импортом; затем glb кладётся в
   `mods/pax_rpg/models/`.

Как устроено:
- Правая рука ставится своим двухкостным IK (`solve_arm`): кисть держит рукоять в заданной точке, клинок
  смотрит в заданную сторону; крен меча вокруг клинка подбирается так, чтобы запястье гнулось меньше всего,
  а кручение уходит в предплечье (цилиндр — его не видно).
- Место меча на спине (WeaponBack) берётся из позы хвата — переключение «спина → рука» (ключ влияния
  ограничения Hand на кадрах 9→10) проходит без скачка. При экспорте ограничения запекаются в кости.
- Ключи пишутся с отцепленным действием: иначе каждое обновление сцены возвращает костям уже записанные
  значения и затирает позу. В Blender 5 действию нужен ещё и слот (`action_slot`).
- В glb — только эти пять анимаций (дорожки NLA): в рабочем файле лежат и действия Meshy-героя с теми же
  именами костей.

Шаг ходьбы ≈ 0,77 м, цикл 0,8 с → 1,9 м/с при скорости анимации 1 (`STRIDE_SPEED` в location.gd).
